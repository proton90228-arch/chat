1. Установщик лаунчера
Причина. Tauri подключает hooks.nsh из src-tauri\windows, а код макроса вставляет позже, в сгенерированный target\release\nsis\x64\installer.nsi. Переменная ${__FILEDIR__} внутри макроса раскрывается в момент вставки. Поэтому makensis искал remove-legacy.ps1 в nsis\x64 и падал, и в итоге оставался только голый .exe. Это я сверил с реальным шаблоном Tauri. Сам makensis прогнать не смог: в песочнице его нет.
Что делать. Замените содержимое src-tauri/windows/hooks.nsh:
; Путь фиксируется здесь, вне макроса: внутри !macro ${__FILEDIR__}
; указывал бы на папку сгенерированного installer.nsi.
!define VALKYRIE_HOOKS_DIR "${__FILEDIR__}"

!if ! /FileExists "${VALKYRIE_HOOKS_DIR}\remove-legacy.ps1"
  !error "Valkyrie: remove-legacy.ps1 is missing next to hooks.nsh (${VALKYRIE_HOOKS_DIR})"
!endif

!macro NSIS_HOOK_PREINSTALL
  DetailPrint "Valkyrie: looking for the legacy MSI launcher..."
  InitPluginsDir
  File "/oname=$PLUGINSDIR\remove-legacy.ps1" "${VALKYRIE_HOOKS_DIR}\remove-legacy.ps1"
  nsExec::ExecToLog 'powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File "$PLUGINSDIR\remove-legacy.ps1"'
  Pop $0
  DetailPrint "Valkyrie: legacy cleanup finished (code $0)"
!macroend

!macro NSIS_HOOK_POSTINSTALL
!macroend
!macro NSIS_HOOK_PREUNINSTALL
!macroend
!macro NSIS_HOOK_POSTUNINSTALL
!macroend
Затем:
Удалите пустой src-tauri/remove-legacy.ps1, который создавали по совету другого агента. Настоящий скрипт лежит в src-tauri/windows/.
Запустите npm run tauri build. Установщик появится в target\release\bundle\nsis\.
Если makensis вдруг ругнётся на строку !if, удалите эти 3 строки проверки. Само исправление делает строка !define.
